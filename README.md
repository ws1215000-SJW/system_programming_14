# 발전소 복구 시뮬레이션

시프 14조 조별 과제

- [시설 프로세스와 화면](https://github.com/ws1215000-SJW/system_programming_14/blob/main/docs/facility-ui.md)

**주제** · Linux 시스템 프로그래밍을 활용한 2인 비대칭 협동 발전소 복구 시뮬레이션

발전소 직원은 현장의 장치와 고장 상태를 볼 수 있고, 관제사는 세 시설의 계측값과 정비 기록을 볼 수 있습니다. 두 사람이 장치 ID와 복구 절차를 주고받으면 직원이 현장에서 수리합니다. 게임은 실제 파일 권한, 심볼릭 링크, 설비 프로세스 상태와 계측값을 검사해 복구 여부를 판정합니다.

## 빌드 및 실행

같은 컴퓨터의 Linux 또는 같은 WSL 배포판에서 터미널 두 개를 엽니다. 호스트는 루프백 주소 `127.0.0.1:12345`에서 접속을 받습니다. 두 터미널 모두 **저장소 루트**로 이동하세요. 직원은 현재 디렉터리를 기준으로 현장 데이터 `plant/`를, 관제사는 정비 기록 `archive/`를 찾습니다.

### 1. 두 프로그램 빌드

GCC, Make, ncursesw 개발 라이브러리가 필요합니다. Ubuntu 또는 Debian에서는 다음 명령으로 준비할 수 있습니다.

```sh
sudo apt install build-essential libncurses-dev
```

한 터미널에서 아래 두 명령을 실행합니다. `make`는 직원 프로그램 `worker`와 설비 프로그램 `equip`을 만들고, 두 번째 명령은 관제사 프로그램을 만듭니다.

```sh
make
gcc -Isrc client/*.c src/ui.c src/timeutil.c -lncursesw -lm -o control_client
```

### 2. 직원 실행 후 관제사 접속

직원 프로그램을 시작하면 첫 이벤트의 대기 시간이 흐릅니다. 두 프로그램의 빌드를 마치고 터미널을 모두 준비한 뒤 실행하세요.

**터미널 1 · 직원 호스트**

```sh
./worker
```

**터미널 2 · 관제사 클라이언트**

```sh
./control_client
```

접속하면 **관제사 게임 콘솔**에 아래 명령을 입력합니다. `ready`는 직원에게 준비 완료를 알리고, `ls`는 탐색할 기록 목록을 보여줍니다.

```text
ready
ls
```

기본 화면은 ncurses를 사용합니다. 두 터미널을 80열 × 24행 이상으로 확보하고 한글이 깨지면 UTF-8 로캘을 확인하세요. 직원 화면을 줄 단위로 쓰려면 터미널 1에서 `WORKER_PLAIN=1 ./worker`로 실행하세요. WSL의 Windows 드라이브 등에서 POSIX 권한 변경이 반영되지 않으면 직원 프로그램이 현장 데이터를 Linux 임시 디렉터리에 복사해 사용하고 종료 시 정리합니다. 권한 변경이 지원되는 환경에서는 저장소의 현장 파일을 직접 사용합니다.

## 두 사람의 역할

| 역할 | 볼 수 있는 정보 | 하는 일 | 상대에게 전달할 정보 |
| --- | --- | --- | --- |
| 발전소 직원 · `worker` | 현재 시설의 계기판, 장비 명판, 설정 파일, 링크와 설비 프로세스 | 현장 조사, 설정 변경, 링크 복구, 설비 재개·재실행 | 장치 ID, 오류 상태, 실측값, 현장에서 발견한 인증 코드 |
| 관제사 · `control_client` | 세 시설의 계측값과 복구율, 정비 매뉴얼과 교체 이력 | 현장 장치를 기록과 대조하고 복구 절차 안내 | 해당 모델의 정상 기준, 연결할 대상 파일명, 조작 순서 |

**첫 이벤트에서 협력하는 법**

1. C01 경보가 뜨면 직원은 **직원 게임 콘솔**에서 아래 명령을 차례로 입력합니다.

   ```text
   go cooling
   ls
   status
   ```

2. 직원은 `ls`에 나온 명판을 `cat <명판 파일>`로 읽고 `say <펌프 ID와 현재 유량>`으로 보고합니다. 설정 파일에서 읽은 **목표 유량**과 `status`의 **실측 유량**을 구분하세요. 꺾쇠괄호에는 화면에서 확인한 이름이나 내용을 넣습니다.
3. 관제사는 `ls`, `cd`, `cat`으로 냉각 설비 기록을 탐색하고 해당 펌프의 정상 기준을 찾아 `say <조정할 값>`으로 전달합니다.
4. 직원은 `help`에서 해당 설정의 `repair` 문법을 확인해 적용합니다. **추가 조작 필요**가 뜨면 설정이나 설비를 다시 조사하고, **회복 확인 중**이면 다음 계측 보고를 기다리세요.

직원의 `ls`는 현재 시설의 활성 이벤트에 필요한 조사 파일만 보여줍니다. 조사에 `ps`나 `status`만 필요하면 해당 명령을 안내합니다. 관제사의 `ls`는 현재 관제 기록 디렉터리의 목록입니다. 관제사가 파일명을 알려주면 직원은 자기 목록에 표시되지 않은 이름도 해당 시설에서 허용된 대상에 한해 직접 입력할 수 있습니다.

## 이벤트와 승패

이벤트마다 수리 제한 시간은 **300초**입니다. 직원의 조작이 검증을 통과하면 해당 시설의 복구율이 올라가고 표의 다음 이벤트가 예약됩니다. 순서는 **C01 → C02 → C03 → P01 → P02 → P03 → G01 → G02 → G03**으로 고정됩니다. 최종 G03 복구에 성공하면 클리어하고, 진행 중인 이벤트의 제한 시간이 만료되면 게임 오버입니다.

| 코드 | 시설 | 고장 | 함께 조사할 정보 |
| --- | --- | --- | --- |
| C01 | 냉각실 | 냉각수 유량 저하 | 펌프 ID, 목표 유량, 실측 유량과 냉각 효율 |
| C02 | 냉각실 | 냉각 펌프 프로세스 정지 | 펌프 PID·상태와 상태별 복구 절차 |
| C03 | 냉각실 | 냉각 센서 데이터 경로 손상 | 연결된 센서 ID, 교체 이력, 데이터 갱신 시각 |
| P01 | 배전실 | 배전 회로 과부하 | 회로 ID, 현재 부하, 회로별 허용 부하 |
| P02 | 배전실 | 배전 차단기 비정상 정지 | 고장 회로와 차단기 ID, 격리 상태, 재가동 조건 |
| P03 | 배전실 | 전력 부하 불균형 | 분기별 장치 ID와 실측 전력, 정상 배분 기준 |
| G01 | 발전실 | 발전기 온도 센서 연결 오류 | 센서 링크, 교체 기록, 센서별 연결 경로 |
| G02 | 발전실 | 터빈 제어 프로세스 정지 | 터빈 PID·상태, 재개·재실행 조건, 발전량 |
| G03 | 발전실 | 발전기 최종 재가동 실패 | 부품 일련번호, 설정 파일 권한, 다른 두 시설의 정상 작동 여부 |

한 시설의 고장은 다른 시설의 계기판에도 나타날 수 있습니다. 예를 들어 C01에서는 냉각수 유량 저하가 발전실 온도에도 영향을 줍니다. 이때 두 사람은 C01의 남은 시간 안에 냉각실의 원인을 해결합니다.

## 게임 콘솔 명령어

아래 명령은 게임 실행 후 각 역할의 입력줄에 입력합니다. 파일과 설비를 다루는 명령은 게임이 허용한 현장 디렉터리와 프로세스에 적용됩니다.

### 발전소 직원

| 명령 형식 | 하는 일 |
| --- | --- |
| `help` | 조사·수리 명령과 세부 사용법을 봅니다. |
| `go <시설>` | `cooling`, `power`, `generator` 중 한 시설로 이동합니다. |
| `status` | 현재 시설이 최근 보고한 계측값을 확인합니다. |
| `ls` | 현재 이벤트에서 직접 조사할 파일 또는 조사 방법을 확인합니다. |
| `cat <파일>` | 현장 메모, 명판, 설정값, 센서 데이터 등 파일 내용을 읽습니다. |
| `stat <파일>` | 권한·수정 시각·링크 여부를 확인합니다. 센서 링크에서는 연결된 센서 ID도 확인할 수 있습니다. |
| `ps` | 현재 시설의 설비 PID와 실행 상태를 확인합니다. |
| `rm <링크>` | 센서 고장 이벤트의 링크만 제거하며 센서 원본은 보존합니다. |
| `ln <센서 파일> <링크>` | 첫 인자의 센서 파일을 가리키는 링크를 둘째 이름으로 만듭니다. 기존 링크는 먼저 제거합니다. |
| `chmod <모드> <파일>` | 권한 복구 이벤트에서 허용된 파일에 8진수 권한을 적용합니다. |
| `repair <항목> <값...>` | 유량·회로 부하·전력 배분 등 현장 설정을 조정합니다. |
| `resume <설비>` | 정지된 설비를 재개합니다. |
| `restart <설비>` | 종료된 설비를 재실행합니다. |
| `say <내용>` | 관제사에게 현장 정보를 보냅니다. |
| `quit` | 직원 콘솔을 종료합니다. |

### 관제사

| 명령 형식 | 하는 일 |
| --- | --- |
| `help` | 관제사 명령을 확인합니다. |
| `ready` | 직원에게 준비 완료를 알립니다. |
| `status` | 수신한 시설 상태와 이벤트 정보를 확인합니다. |
| `ls` | 현재 디렉터리의 관제 기록 목록을 봅니다. |
| `cd [경로]` | 기록 디렉터리를 이동합니다. 인자 없는 `cd`는 기록 최상위로 돌아갑니다. |
| `cat <파일>` | 정비 매뉴얼과 교체 이력을 읽습니다. |
| `stat <파일>` | 기록의 수정 시각 등 메타데이터를 확인합니다. |
| `unlock <파일명> <코드>` | 현장에서 전달받은 코드로 제한 문서를 해제합니다. |
| `say <내용>` | 직원에게 조사 결과와 복구 절차를 보냅니다. |
| `quit` 또는 `/quit` | 관제사 콘솔을 종료합니다. |

## 시스템 구조

```text
관제사 클라이언트 ── TCP ── 직원 호스트
                              ├─ 파이프·시그널 ─ 발전실 ─ 터빈 제어 프로세스
                              ├─ 파이프·시그널 ─ 냉각실 ─ 펌프 프로세스
                              └─ 파이프·시그널 ─ 배전실 ─ 차단기 제어 프로세스
```

| 기술 | 게임에서 쓰이는 곳 |
| --- | --- |
| 프로세스와 시그널 | 호스트가 시설 자식 프로세스를 생성하고 각 시설이 설비를 관리합니다. `fork`·`exec`로 설비를 실행하고 `waitpid`로 정지·종료·재개를 구분합니다. |
| 파이프와 수리 검증 | 호스트는 수리 조작 후 파일과 최근 계측을 확인하고 시설에 검증 시그널을 보냅니다. 시설이 실제 상태를 재검사해 파이프로 결과를 돌려주면 호스트가 성공을 반영합니다. |
| 파일 시스템 | 설정 파일의 값, 심볼릭 링크 대상, 접근 권한, 센서 데이터의 갱신 시각이 복구 조건에 사용됩니다. |
| TCP와 입출력 다중화 | 호스트와 관제사가 길이 헤더가 있는 메시지로 채팅·계측·이벤트·승패를 교환합니다. 호스트는 `poll`로 입력·시설 보고·소켓을 감시하고 관제사는 `select`로 소켓 수신을 확인합니다. |
| 시간과 화면 | 단조 시계(`CLOCK_MONOTONIC`)로 이벤트 시간을 계산하고, ncurses로 직원의 현장 계기판과 관제사의 전체 시설 화면을 그립니다. |
